## The idea

Running ThunderID from source gives you the same three deployments as the quickstart pack, with the frontends on hot-reloading dev servers.

## Prerequisites

Git, Go (version in `backend/go.mod`), Node.js LTS, pnpm, `sqlite3` and `openssl`. On Windows, PowerShell 7 too. For debugging: Delve and the VS Code Go extension.

## Get the code

Fork [thunder-id/thunderid](https://github.com/thunder-id/thunderid), clone your fork, and add the main repo as `upstream`.

## Run it

| Goal | Command | What you get |
| --- | --- | --- |
| Everything, like the quickstart pack | `make run` | DP on 8090, auth-dp on 8091, CP on 8095, Gate on 5190, Admin Console on 5192, CP Console on 5193 |
| Only the data plane side | `make run_dp` | DP, its Admin Console and the Gate dev server |
| Only the control plane side | `make run_cp` | CP, its console and auth-dp |
| One backend, frontends separately | `make run_backend` + `make run_frontend` | An all-in-one backend and the full Console on 5191, easier to debug |

`make run` keeps databases, keys and secrets in `target/dev-quickstart/`. Delete it to start clean. With `make run_backend`, seed data once with `go run -C backend/cmd/server . bootstrap --admin-password admin` (see the debugging guide for the full command).

## Test it

| What | Command |
| --- | --- |
| Backend unit tests | `make test_unit` |
| Backend integration tests | `make test_integration` (needs `make build_backend` first) |
| One integration test | `make test_integration RUN="TestName"` |
| Frontend unit tests | `make test_frontend` |
| Playwright end-to-end | `make test_e2e` |
| The checks to run before opening a PR | `make pr_checks` |
| Regenerate mocks after changing an interface | `make mockery` |

New code needs at least 80% coverage. CI runs more than `make pr_checks`: integration tests against PostgreSQL and Redis, control plane and pack integration tests, Playwright and CLI end-to-end tests, and the docs build.

## Debug it

Run `make run_backend` once, so the certificates, keys and databases exist. Then start the data plane under [Delve](https://github.com/go-delve/delve) and attach from VS Code (a Go "attach to remote" configuration on port 2345):

```bash
cd backend/cmd/server
dlv debug --headless --listen=127.0.0.1:2345 --api-version=2 --accept-multiclient --continue -- .
```

The `make debug_backend` target is broken on `main` today: the `build.sh` function behind it was removed.

## Where the rules live

`AGENTS.md` at the repo root and in `backend/` and `frontend/`, and the skills under `.agent/skills/`. They're written for humans and AI coding agents alike.


## Recap

- `make run` gives you the full quickstart layout from source.
- `make pr_checks` is the gate before a PR. CI runs more on top of it.
- Debug the backend by running it under Delve.
- `AGENTS.md` files and `.agent/skills/` hold the coding rules.
