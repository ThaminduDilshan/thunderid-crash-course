An organization unit (OU) is a node in a tree that owns resources. Think departments in a company, or one customer organization each in a B2B product.

- **What lives in an OU:** users, agents, applications, groups, roles, user and agent types, connections and resource servers. Every entity row has a non-null OU.
- **ID vs handle:** every OU has a generated `id` and a human `handle`. A handle only needs to be unique among its siblings, so a full path like `acme/engineering` identifies an OU. `/organization-units/tree/{path}` resolves one.
- **The system OU:** the bootstrap OU (handle `default`) set by `server.system_ou_id`. A resource that names no OU lands there. It can't be deleted, and no OU can be deleted while child OUs, users or groups still depend on it.
- **An OU can carry its own sign-in setup:** flows, theme, layout, logo and terms of service, which apps signing in there inherit.

## Signing in to an OU (2.0)

Every sign-in lands in exactly one OU, and both the user and the application must be found there.

- An app picks the OU with `/ou/{ouId}/oauth2/authorize` and `/ou/{ouId}/oauth2/token`, or with `ouId` on `/flow/execute`. These take the OU's ID, not its handle.
- Or a Resolve OU step in the flow decides it after the user is identified. Put it before the Authorization step, so only that OU's role assignments count.
- Tokens carry `ouId`, `ouHandle` and `ouName` claims.

## Sharing across OUs (2.0)

An application, user or role lives in one OU but can be shared into others with sharing policies: to all units, to child units (all or selected, one unit or its whole subtree), or to other tree roots. This is how one B2B app serves many customer OUs without being copied. Groups are never shared.

## 🧪 Lab

```bash
curl -sk -X POST $CP/organization-units -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"handle":"acme","name":"Acme","parent":null}'
```

Create a child under it with `"parent":"<acme-id>"`, then `GET $CP/organization-units/tree/acme/<child-handle>`. In the console, share your app into `acme` and sign in through `/ou/<acme-id>/oauth2/authorize` with a user created in `acme`.
