## The idea

You could write the OAuth redirects, PKCE, token storage, refresh and flow rendering by hand. The SDKs do it for you, and they're how ThunderID itself is built: Gate and the consoles run on `@thunderid/react`.

## Pick your SDK

| Platform | Repository | Packages |
| --- | --- | --- |
| JavaScript | [javascript-sdks](https://github.com/thunder-id/javascript-sdks) | Core `@thunderid/javascript`, runtimes `browser` and `node`, frameworks `react`, `vue`, `nextjs`, `nuxt`, `express`, routers `react-router` and `tanstack-router`, and a `better-auth` helper |
| iOS | [ios-sdks](https://github.com/thunder-id/ios-sdks) | `ThunderID` (Swift) and `ThunderIDSwiftUI` components |
| Android | [android-sdks](https://github.com/thunder-id/android-sdks) | `dev.thunderid.android` (Kotlin) and `dev.thunderid.compose` components |
| Flutter | [flutter-sdks](https://github.com/thunder-id/flutter-sdks) | `thunderid_flutter`, a plugin over the native iOS and Android SDKs |

Python, Go, Angular and React Native SDKs are listed as coming soon. Agent tooling (agent skills, Claude and Codex plugins) is in the same [SDKs and tools](https://thunderid.dev/sdks-and-tools) catalogue.

:::info[🧳 In Wayfinder]

The Wayfinder web app is a React app on `@thunderid/react` in redirect mode. The B2B edition, Wayfinder Enterprise, is a Next.js app on `@thunderid/nextjs`, which signs people in from the server.

:::

## Two modes, one SDK

The UI SDKs support both sign-in models from [module 11](/docs/next/intermediate/three-ways-to-sign-in). In React, the provider's props pick the mode:

| Mode | `ThunderIDProvider` props | Example |
| --- | --- | --- |
| Redirect (ThunderID-hosted sign-in) | `clientId` + `baseUrl` | `samples/apps/react-sdk-sample` |
| App-native (Flow Execution API) | `applicationId` + `baseUrl` | Gate itself, the Wayfinder sample's [app-native mode](https://github.com/thunder-id/thunderid/blob/main/samples/apps/wayfinder-sample/APP_NATIVE.md) |

`clientId` vs `applicationId` is the difference to remember. A redirect app that also offers sign-up sets both (Ex: Wayfinder), since sign-up runs on the Flow Execution API. Components such as `<SignIn/>` and `<SignUp/>` draw flow steps from the server's response, so a flow change shows up in the app without a release. `<UserProfile/>` edits the profile through `/users/me`.

A browser SPA signs in only through redirect mode. It still uses the Flow Execution API for sign-up and recovery, which have no redirect equivalent.

## 🧪 Lab

Pick a second SDK from the [SDKs and tools](https://thunderid.dev/sdks-and-tools) catalogue (Next.js, Vue, Express or a mobile SDK) and run its quickstart against your data plane. Compare what the server-side SDKs keep in the browser with what the React SDK keeps.

## Recap

- One SDK repository per platform, with a quickstart and a playground in each.
- `clientId` is for redirect sign-in. `applicationId` is for Flow Execution API calls, so a redirect app with sign-up sets both.
- SDK components draw whatever the flow asks for, so flows can change without app releases.

Go deeper: [SDKs and tools](https://thunderid.dev/sdks-and-tools), [samples repository](https://github.com/thunder-id/samples).
