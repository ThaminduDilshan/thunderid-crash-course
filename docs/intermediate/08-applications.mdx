An application is anything that signs users in through ThunderID or calls it with its own credentials. Under the hood it's an entity of category `app`, plus two profiles:

- **Inbound auth profile:** which flows it uses, its theme and layout, `allowedUserTypes` and `allowedAgentTypes` <V2 />, the token `subjectAttribute`, login consent and attestation.
- **OAuth profile** (`inboundAuthConfig`): grant types, redirect URIs, client authentication method, PKCE, public or confidential, PAR, DPoP, token lifetimes and the claims each token carries.

## Application types

The `type` is required and can't change after creation.

| Type | For | Signs in through |
| --- | --- | --- |
| `browser` | SPAs (React, Vue, plain JS) | Redirect only, authorization code + PKCE, public client |
| `fullstack` | Server-rendered apps (Next.js, Express) | Redirect, or app-native with a Flow Secret |
| `mobile` | iOS, Android, Flutter | Redirect, or app-native with platform attestation |
| `m2m` | Backend services | `client_credentials` only, no user sign-in |
| `mcp` | MCP clients | Redirect (authorization code + refresh) |
| `custom` | Anything else, and apps registered through DCR | Depends on its OAuth profile |

The console's **templates** (React, Next.js, Android, Wallet, etc.) only prefill these settings and record which template was used. One exception: issuing verifiable credentials requires a wallet template ([module 14](/docs/advanced/verifiable-credentials)).

## Things to remember

- A public client must use client auth method `none` and PKCE.
- The client secret is shown once, in the create response. Regenerate it with `POST /applications/{id}/client-secret/regenerate`.
- The token `sub` is the user's ID unless `subjectAttribute` maps a user type to another unique attribute (Ex: email).
- Leave a flow ID empty and the app gets the OU or server default flow ([module 7](/docs/beginner/flows)).

## 🧪 Lab

Create an M2M app and get a token for it:

```bash
curl -sk -X POST $CP/applications -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"Orders Worker","type":"m2m","inboundAuthConfig":[{"type":"oauth2","config":{"grantTypes":["client_credentials"],"tokenEndpointAuthMethod":"client_secret_basic","publicClient":false,"pkceRequired":false}}]}'

curl -sk -u '<client-id>:<client-secret>' -d grant_type=client_credentials $DP/oauth2/token | jq
```

Then create a `browser` app from the React template in the console. Compare its OAuth settings with the M2M app's.
