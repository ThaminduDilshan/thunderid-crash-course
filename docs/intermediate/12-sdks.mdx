The SDKs wrap the protocols and the Flow Execution API so an app doesn't hand-roll redirects, PKCE, token storage, refresh or flow rendering. Each SDK repository ships a quickstart sample and a playground.

| Platform | Repository | Packages |
| --- | --- | --- |
| JavaScript | [javascript-sdks](https://github.com/thunder-id/javascript-sdks) | Core `@thunderid/javascript`, runtimes `browser` and `node`, frameworks `react`, `vue`, `nextjs`, `nuxt`, `express`, routers `react-router` and `tanstack-router`, and a `better-auth` helper |
| iOS | [ios-sdks](https://github.com/thunder-id/ios-sdks) | `ThunderID` (Swift) and `ThunderIDSwiftUI` components |
| Android | [android-sdks](https://github.com/thunder-id/android-sdks) | `dev.thunderid.android` (Kotlin) and `dev.thunderid.compose` components |
| Flutter | [flutter-sdks](https://github.com/thunder-id/flutter-sdks) | `thunderid_flutter`, a plugin over the native iOS and Android SDKs |

Python, Go, Angular and React Native SDKs are listed as coming soon. Agent tooling (agent skills, Claude and Codex plugins) sits in the same [SDKs & tools](https://thunderid.dev/docs/next/sdks-and-tools) catalogue.

## Two modes

The UI SDKs support both sign-in models from [module 9](/docs/intermediate/three-ways-to-sign-in). In React the provider's props pick the mode:

| Mode | `ThunderIDProvider` props | Example |
| --- | --- | --- |
| Redirect (ThunderID-hosted sign-in) | `clientId` + `baseUrl` | `samples/apps/react-sdk-sample` |
| App-native (Flow Execution API) | `applicationId` + `baseUrl` | Gate itself, `samples/apps/react-api-based-sample` |

`clientId` vs `applicationId` is the distinction to remember. Components such as `<SignIn/>`, `<SignUp/>` and `<UserProfile/>` render flow steps from the server's response, so a flow change in the server shows up in the app without a redeploy.

The product dogfoods the SDK: Gate and the consoles are built on `@thunderid/react`. A capability is expected in every SDK it applies to, so SDK pull requests carry a parity check ([module 22](/docs/contributor/how-work-gets-done)).

A browser SPA signs in only through redirect mode. It still uses the Flow Execution API for sign-up and recovery, which have no redirect equivalent. App-native sign-in is for native mobile apps and confidential server-side apps ([module 9](/docs/intermediate/three-ways-to-sign-in)).

🧪 **Lab:** follow the [React quickstart](https://thunderid.dev/docs/next/getting-started/connect-your-application/react) against your Lab 0 data plane. Watch the browser's network tab: `/oauth2/authorize`, the `/flow/execute` calls Gate makes, then `/oauth2/token`.
