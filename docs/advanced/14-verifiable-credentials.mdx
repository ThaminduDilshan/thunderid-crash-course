title: "14. Verifiable credentials"
sidebar_label: "14. Verifiable credentials"

A verifiable credential (VC) is a signed statement about someone (Ex: "over 18", "employee of Acme") that they keep in a digital wallet and present when needed. Three roles: the **issuer** signs it, the **holder** keeps it, the **verifier** checks it. ThunderID can be the issuer and the verifier.

| Role | Standard | In ThunderID |
| --- | --- | --- |
| Issuer | [OpenID4VCI](https://openid.net/specs/openid-4-verifiable-credential-issuance-1_0.html) | Credential configurations at `/openid4vci/credential-configurations` (format `dc+sd-jwt`). Wallets use `/.well-known/openid-credential-issuer`, credential offers, `/openid4vci/nonce` and `/openid4vci/credential`. |
| Verifier | [OpenID4VP](https://openid.net/specs/openid-4-verifiable-presentations-1_0.html) | Presentation definitions at `/openid4vp/presentation-definitions`. A flow verifies a wallet presentation with the `OpenID4VPVerifyExecutor`, so a wallet can be a sign-in method. |

**Setup gotchas:**

- Issuance offers use the authorization code grant only, and an offer lives 5 minutes.
- The wallet's application must be created from the `wallet` template. The issuer refuses other clients.
- Verification needs `client_id_scheme` and a `signing_key_id` backed by an X.509 certificate, or the server won't start with it enabled.

🧪 **Lab:** run the [VC try-it-out](https://thunderid.dev/docs/next/use-cases/vc/overview) with a test wallet.
