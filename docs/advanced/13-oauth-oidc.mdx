What the data plane implements, checked against the code on `main`. Each row links to its guide.

| Capability | Spec | Endpoint or setting |
| --- | --- | --- |
| [Authorization code](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/authorization-code) | RFC 6749 | `/oauth2/authorize`, `/oauth2/token` |
| [PKCE](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/pkce) | RFC 7636 | `S256` only |
| [Client credentials](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/client-credentials) | RFC 6749 | `grant_type=client_credentials` |
| [Refresh token](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/refresh-token) | RFC 6749 | Rotated on use by default |
| [Token exchange](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/token-exchange) | RFC 8693 | Also how assertions become tokens |
| [Identity assertion grant](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/identity-assertion-grant) | IETF draft (ID-JAG) | JWT bearer grant, on when `id_jag.acceptance` is set |
| [Device authorization](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/device-authorization) <V2 /> | RFC 8628 | `/oauth2/device-authorize` |
| [CIBA](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/backchannel-authentication) | OpenID CIBA Core | `/oauth2/bc-authorize`, poll mode |
| [PAR](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/par) | RFC 9126 | `/oauth2/par` |
| [DPoP](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/dpop) | RFC 9449 | Per-app `dpopBoundAccessTokens` |
| [Rich authorization requests](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/rich-authorization-requests) <V2 /> | RFC 9396 | `authorization_details`, types at `/oauth2/authorization-details-types` |
| [Resource indicators](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/resource-indicators) | RFC 8707 | `resource` parameter, one per request |
| [Introspection](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/token-introspection) | RFC 7662 | `/oauth2/introspect` |
| [Revocation](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/token-revocation) | RFC 7009 | `/oauth2/revoke`, when enabled |
| [Dynamic client registration](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/dynamic-client-registration) | RFC 7591, 7592 | `/oauth2/dcr/register`, when enabled |
| [OpenID Connect](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/openid-connect), [UserInfo](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/userinfo) | OIDC Core 1.0 | ID token, `/oauth2/userinfo` |
| [RP-initiated logout](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/rp-initiated-logout) | OIDC RP-Initiated Logout | `end_session_endpoint` |
| [Back-channel logout](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/backchannel-logout) <V2 /> | OIDC Back-Channel Logout | Per-app `backchannelLogoutUri` |
| [Server metadata](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/server-metadata) | RFC 8414, OIDC Discovery | `/.well-known/openid-configuration`, `/.well-known/oauth-authorization-server` |
| [Issuer identification](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/issuer-identification) | RFC 9207 | `iss` on authorization responses |
| [JWKS](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/jwks) | RFC 7517 | `/oauth2/jwks` |
| [Client authentication](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/client-authentication-methods) | RFC 6749, RFC 7523 | `client_secret_basic`, `client_secret_post`, `private_key_jwt`, `none` |
| [Token formats](https://thunderid.dev/docs/next/guides/protocols/oauth-oidc/token-formats) | RFC 9068, JWS, JWE | Access tokens are `at+jwt`. ID token and UserInfo can be signed, encrypted or both. |

**Not supported today:** JWT-secured authorization requests (`request`, `request_uri`), `client_secret_jwt`, mutual TLS client authentication, and response types other than `code`.

🧪 **Lab:** `curl -sk $DP/.well-known/openid-configuration | jq '.grant_types_supported, .code_challenge_methods_supported, .dpop_signing_alg_values_supported'`. Then pick one row you haven't used and follow its guide end to end.

The server runs the [OpenID conformance suite](https://github.com/thunder-id/thunderid/actions/workflows/oidc-conformance-test.yml) in CI.
